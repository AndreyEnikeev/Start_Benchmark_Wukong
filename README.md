# Benchmark Wukong — Автозапуск

Приложение для автоматического прогона встроенного бенчмарка **Black Myth: Wukong Benchmark Tool** в двух режимах — CPU и GPU. Само настраивает `GameUserSettings.ini`, запускает бенчмарк, снимает скриншот с результатами, распознаёт цифры через OCR и открывает окно с отчётом.

## Важно

Об одной особенности проекта. При разработке я сознательно отказался от любых NuGet-пакетов. Всё, что использует программа — это то, что уже встроено в Windows и .NET: Microsoft.Win32.Registry, System.Diagnostics, System.Runtime.InteropServices (P/Invoke к WinAPI),
System.Windows.Media.Imaging (WPF), а для OCR — встроенный в саму Windows движок Windows.Media.Ocr (WinRT). Никаких Tesseract, Emgu.CV, Newtonsoft.Json и прочих сторонних библиотек. Нужно ли это по заданию — не знаю, но я решил для себя, что не буду их использовать

## 1. Что нужно для запуска

| Компонент | Требование |
|---|---|
| ОС | Windows 10 / 11 (x64) |
| .NET | .NET 8.0 |
| Steam | Установлен, выполнен вход в аккаунт |
| Бенчмарк | **Black Myth: Wukong Benchmark Tool** (AppID **3132990**) установлен в любой библиотеке Steam |
| OCR | Языковой пакет **русского языка** для Windows OCR (Параметры → Время и язык → Язык → Русский → Речь и рукописный ввод) |
| Права | Обычные права пользователя (админ не требуется) |

> Бенчмарк обязательно должен быть **хотя бы раз запущен вручную** — иначе у него нет `GameUserSettings.ini`. Приложение умеет генерировать конфиг сам (шаг 1), но это занимает до 10 минут из-за компиляции шейдеров.

## 2. Как запустить

### 2.1. Шаг 1. Установка бенчмарка через Steam

Бенчмарк распространяется бесплатно в Steam под AppID **3132990** и называется **Black Myth: Wukong Benchmark Tool**.

1. Откройте Steam и войдите в свой аккаунт.
2. В верхнем меню выберите **«Библиотека»** → в строке поиска справа введите `3132990` или `Black Myth Wukong Benchmark`.
3. В результатах появится страница бенчмарка. Нажмите **«Установить»**.
4. В окне выбора диска укажите **любой** — программа умеет находить бенчмарк во **всех библиотеках Steam**, а не только в системной. Файл `libraryfolders.vdf` парсится автоматически.
5. Дождитесь окончания загрузки (~8 ГБ). Бенчмарк появится в библиотеке как отдельная «игра».

> **Если бенчмарк уже установлен** — этот шаг можно пропустить. Программа сама найдёт его по манифесту `appmanifest_3132990.acf` в папке `steamapps` любой библиотеки.

### 2.2. Шаг 2. Сборка проекта

Есть два варианта — выберите удобный.

**Через Visual Studio:**
1. Откройте файл решения `.sln` в Visual Studio 2022 (или новее).
2. Убедитесь, что в верхней панели выбрана конфигурация **Release** и платформа **x64** (или **Any CPU** — зависит от `.csproj`).
3. Меню **Build → Rebuild Solution** (или `Ctrl + Shift + B`).
4. Если сборка прошла успешно — в папке `bin\Release\netX.X\` появится `Start_Benchmark_Wukong.exe`.

**Через консоль:**
1. Откройте PowerShell или cmd.
2. Перейдите в папку с проектом: `cd путь\к\Start_Benchmark_Wukong`.
3. Выполните `dotnet build -c Release`.
4. Готовый `.exe` появится в `bin\Release\netX.X\`.

### Что происходит по шагам

| Шаг | Действие | Длительность |
|---|---|---|
| 1/5 | Проверка Steam и наличия бенчмарка. Если нет `GameUserSettings.ini` — запускаем бенчмарк только ради его генерации | до 10 мин (только при первом запуске из-за компиляции шейдеров) |
| 2/5 | Сбор характеристик ПК (CPU, GPU, RAM, экран, ОС, BIOS) | секунды |
| 3/5 | Настройка конфига под **CPU-режим**, запуск бенчмарка, OCR-распознавание результата | ~4–5 мин |
| 4/5 | Настройка конфига под **GPU-режим**, запуск бенчмарка, OCR-распознавание результата | ~4–5 мин |
| 5/5 | Открытие окна с отчётом (характеристики + результаты + параметры тестов) | мгновенно |

> **Важно:** во время теста **не трогайте мышь и клавиатуру**. Приложение эмулирует клики и нажатия; посторонний ввод может сбить сценарий.

### Кнопка «Отмена»

Прерывает текущий сценарий и закрывает окно. Используйте, если бенчмарк завис или вы случайно запустили его на неподходящем железе.

### Где искать результаты

- Окно отчёта открывается автоматически по завершении.
- Скриншоты сохраняются рядом с `.exe` в папке `screenBenchmark` в файлы вида `benchmark_result_ГГГГММДД_ЧЧММСС.png`.
- В окне отчёта у каждой вкладки есть кнопка **«Открыть скриншот»**.

## 3. Обоснование настроек

Бенчмарк хранит настройки в двух местах `GameUserSettings.ini`:

- секция `[ScalabilityGroups]` — ключи `sg.*Quality` (значения `0..4`) и `sg.ResolutionQuality` (в процентах);
- строка `UISettingData=(...)` — «человеческие» настройки из меню игры.

Плюс отдельные ключи верхнего уровня: `bUseVSync`, `bUseDynamicResolution`, `FrameRateLimit`, разрешение окна рендера и т.д.

### 3.1. Общие настройки (для обоих режимов)

Эти параметры фиксированы для **обоих** тестов, чтобы измерять «чистую» производительность без маркетинговых ускорителей:

| Параметр | Значение | Почему так |
|---|---|---|
| `Vsync` / `bUseVSync` | `0` / `False` | VSync ограничивает FPS частотой монитора. На 60 Гц вы бы никогда не увидели реальные 120+ FPS. Для теста синхронизация только мешает. |
| `LockFrameRate` / `FrameRateLimit` | `0` / `0.0` | Ограничение FPS искажает результат. Отключено. |
| `MotionBlur` | `0` | Размытие движения — постэффект, не влияет на нагрузку, но может смазать цифры на скриншоте и усложнить OCR. |
| `InsertFrame` | `0` | Генерация кадров (Frame Generation) — «обманка», которая удваивает FPS без реальной работы GPU. Для честного замера всегда выключена. |
| `SuperResolutionSampling` | `0` | Апскейл из низкого разрешения. Тоже искажает картину, выключен. |
| `bUseDynamicResolution` | `False` | Динамическое разрешение меняет `sg.ResolutionQuality` на ходу. Нам нужен фиксированный масштаб — поэтому выключено. |
| `Dx12` | `1` | DirectX 12 — актуальный API с лучшей многопоточностью. DX11 оставлен в прошлом. |
| `PrivacyAgreement`, `AgreementReaded`, `FirstSettingFinish` | `1` / `True` | Гасят приветственные диалоги, чтобы не мешали автоматизации. |

### 3.2. CPU-режим

| Параметр | Значение | Обоснование |
|---|---|---|
| `QualityLevel` (sg.* / UI) | `0` | Низкое качество. Минимум нагрузки на GPU. |
| Все `*Quality` (тени, текстуры, эффекты и т.д.) | `0` | То же — снимаем нагрузку с видеокарты. |
| `sg.ResolutionQuality` | `33 %` | Рендер в ~⅓ разрешения. GPU практически не работает — все кадры упираются в CPU. |
| Разрешение окна | Минимум монитора, но **не ниже 1280×720** | Слишком низкое разрешение (например, 800×600) может «сломать» рендер. 720p — нижний безопасный предел. |
| `Rtx` | `0` | Трассировка лучей — нагрузка на GPU, здесь не нужна. |
| `RtxLevel` | `0` | То же. |
| `Dlss` | `1` | DLSS (или аналогичный апскейлер) **включён** — дополнительно облегчаем GPU, чтобы CPU успевал стать узким местом. |

### 3.3. GPU-режим

| Параметр | Значение | Обоснование |
|---|---|---|
| `QualityLevel` | `4` | Максимальный общий пресет. |
| Все `*Quality` | `4` | Каждый параметр на максимум — тени, текстуры, эффекты, отражения, глобальное освещение и т.д. |
| `sg.ResolutionQuality` | `100 %` | Нативное разрешение. Никакого даунскейла — GPU работает в полную силу. |
| Разрешение окна | Максимум монитора | Тестируем в том разрешении, в котором вы реально играете. |
| `Rtx` | `1` | Трассировка лучей включена — это самый тяжёлый эффект для современных GPU, без него тест не покажет реальный потенциал карты. |
| `RtxLevel` | `3` | Высокий (но не запредельный) уровень RTX. Уровень `4` есть не на всех картах и не во всех сценах; `3` — компромисс между нагрузкой и стабильностью теста. |
| `Dlss` | `0` | DLSS **выключен** — нужен «честный» FPS, а не искусственно завышенный апскейлером. |

## 4. Известные особенности

- **Первый запуск долгий.** Компиляция шейдеров на слабых системах может занять до 10 минут. Приложение терпеливо ждёт появления `GameUserSettings.ini` и само закроет бенчмарк.
- **Пауза 5 секунд** между CPU- и GPU-тестами оставлена специально — иначе Steam иногда не успевает «отпустить» игру, и второй запуск падает с ошибкой синхронизации.
- **OCR требует русского языка.** Если результаты распознаются как `0`, проверьте: Параметры → Время и язык → Язык и регион → Русский → «Речь и рукописный ввод» должен быть установлен.
- **Все значения в окне результатов — только для чтения**, но их можно выделить и скопировать (значения — `TextBox` без рамки).
- **Настройки теста в окне результатов** — фиксированные надписи (то, что реально было применено к конфигу).

## 5. Частые проблемы

| Симптом | Причина / Решение |
|---|---|
| «Steam не установлен» | Steam не найден ни в реестре, ни в библиотеках. Проверьте установку. |
| «Бенчмарк не найден ни в одной библиотеке Steam» | Бенчмарк не установлен или установлен в нестандартную библиотеку, которую Steam не видит. |
| «Не удалось сгенерировать GameUserSettings.ini» | Запустите бенчмарк вручную, дождитесь окончания компиляции шейдеров, закройте и повторите запуск приложения. |
| «Не удалось распознать результаты» | Нет русского языкового пакета OCR или окно бенчмарка было свёрнуто/перекрыто другим окном при скриншоте. |
| Скриншот чёрный | Бенчмарк в этот момент был в полноэкранном режиме. Закройте лишние окна и не сворачивайте игру. |
